# Как поднять бота на сервере, чтобы он работал всегда

Бот живёт только пока открыт компьютер и запущена консоль. Чтобы он отвечал
круглосуточно и не зависел от вас — нужен сервер (VPS).

---

## Два жёстких условия при выборе сервера

Это не придирки, а то, на чём легко потерять деньги и вечер.

**1. Локация вне России.**

`api.telegram.org` в России блокируется на уровне TCP — проверено замерами:
**пинг проходит, а соединение не устанавливается**. На российском IP бот
запустится без единой ошибки и будет молчать.

Берите локацию **Нидерланды, Германия, Финляндия, Польша или Казахстан**.

**2. Оплата российской картой.**

Многие зарубежные хостинги карты РФ не принимают. Ищите российские хостинги,
у которых есть зарубежные локации — тогда и оплата проходит, и IP не под
блокировками.

---

## Что брать

Бот почти ничего не ест. Самый минимальный тариф:

| Параметр | Сколько нужно |
| --- | --- |
| Ядра | 1 |
| Память | 1 ГБ (хватит с большим запасом) |
| Диск | 10 ГБ |
| ОС | Ubuntu 22.04 или 24.04 |

Ориентир по цене — **150–400 ₽ в месяц** за минимальный тариф.
Цены меняются, поэтому проверяйте на сайте хостинга, а не верьте на слово.

Это примерно 3–8 % от одного заказа на 5000 ₽ — окупается первым же клиентом.

## Установка: одна команда

Подключитесь к серверу:

```bash
ssh root@АДРЕС_СЕРВЕРА
```

Скачайте и запустите скрипт установки:

```bash
curl -fsSL https://raw.githubusercontent.com/n1lokaDeep/telegram-bot-template/main/deploy/setup.sh -o setup.sh
bash setup.sh
```

Скрипт спросит две вещи:

```
BOT_TOKEN: 1234567890:AAHdqTcv...
ADMIN_IDS: 123456789
```

Токен — от [@BotFather](https://t.me/BotFather), свой ID — от
[@userinfobot](https://t.me/userinfobot).

Дальше всё сам: поставит Python и git, создаст отдельного пользователя
(бот не работает от root), склонирует код, соберёт окружение, создаст `.env`
с правами `600`, **прогонит самопроверку до запуска** и настроит службу
systemd.

---

## Что даёт `Restart=always`

Это и есть «держится всегда»:

- сервер перезагрузился → бот поднялся сам;
- бот упал → вернётся через 5 секунд;
- бот потёк по памяти → systemd убьёт и перезапустит (лимит `MemoryMax=512M`).

---

## Управление

| Задача | Команда |
| --- | --- |
| Логи в реальном времени | `journalctl -u tgbot -f` |
| Состояние | `systemctl status tgbot` |
| Перезапустить | `systemctl restart tgbot` |
| Остановить | `systemctl stop tgbot` |
| Править настройки | `sudo -u tgbot nano /opt/tgbot/.env` → `systemctl restart tgbot` |

---

## Обновление бота

Скрипт можно запускать повторно — он обновит код и перезапустит бота,
**не тронув базу данных и `.env`**:

```bash
bash setup.sh
```

---

## Копия базы на всякий случай

База — один файл `bot.db`. Чтобы раз в сутки сохранялась копия, добавьте
задание в cron:

```bash
crontab -e
```

```cron
0 4 * * * cp /opt/tgbot/bot.db /opt/tgbot/backup-$(date +\%F).db
```

## Если что-то не работает

**Бот запущен, но молчит.** Почти всегда это блокировка API. Проверьте:

```bash
curl -s -o /dev/null -w "%{http_code}" --max-time 15 https://api.telegram.org
```

`000` — соединения нет. Либо сервер в России (меняйте локацию), либо нужен
`PROXY_URL` в `.env`.

**`systemctl status` показывает `failed`.** Смотрите причину в логах:
`journalctl -u tgbot -n 50 --no-pager`.

**Заявки не приходят в Telegram.** Проверьте, что вы **нажали Start** у своего
бота. Пока этого не сделано, Telegram запрещает боту писать вам первым.
